# stage2.5.7 — 解读详细度、方向与提示词研究

来源和唯一当前状态入口：[governance/STATE.md](../../../governance/STATE.md) stage2.5.7，衍生自 stage2.5，接续 stage2.5.6.2 的本地 UI 验证。范围：依据用户2026-10-29的请求，检查现有提示词、研究塔罗实践并提出选项方案。本文件是研究记录，不是平级计划，也不授权实现、付费测试、数据库变更或发布。调研日期：2026-10-29。用户随后通过批注认可了本方案；设计已采纳，实施待当前视觉修正之后继续。

## stage2.5.7.1 — 现状与结论

源码事实：`server/ai/prompt.mjs` 的 `stage2.5.4.1-v1` 已要求围绕使用者的问题、原版牌义、正逆位和牌之间的联系形成观察。只发送已揭示牌的文字快照，不发送整套78张牌，也不传牌面图片。包含 `urbanImagery` 文字，因此可以讨论已提供的画面描述，不能假装实际查看图片。自由摆牌坐标不自动代表时间或因果；牌位含义由使用者填写。原始资料没有独立逆位说明，当前逆位解释须注明延伸性质。

当前请求只有模型、计算强度和生成上限，没有回答详细度或关注方向。返回结构固定为整体观察、每张牌、1–3个反思问题和必要限制。整体与单牌之间仍有重复的可能；当前框架已经禁止硬套行动计划、固定天数和积极结论。服务端保留显式生成、重复请求锁和不自动重试的边界，不能因增加预设而削弱。

建议把调整集中在少量可组合的段落，保留这些事实约束。先实现“标准＋综合”的清楚默认，再允许使用者改变详细度和方向。“最高效”尚未得到测量：这次只有源码检查和文献研究，未做新的模型生成、质量评分或成本比较。

## stage2.5.7.2 — 实践来源与取舍

以下是作者或参与者的实践方法；它们不证明预测准确率，也不代表整个塔罗社区的统一意见。部分文章已存在多年，本次联网核对不等于它们是新趋势。

| 实际来源 | 与本项目有关的做法 | 拟采用的边界 |
| --- | --- | --- |
| [Biddy Tarot：提问方式](https://biddytarot.com/blog/the-art-of-asking-powerful-questions/) | 倾向具体、开放、聚焦自身可理解或可采取行动的问题；大问题可拆为牌位 | 保留使用者原话；必要时提出澄清，不暗中改写问题 |
| [Biddy Tarot：把牌读成一个故事](https://biddytarot.com/blog/how-to-tell-the-story-in-the-tarot/) | 结合主题、数字、花色和明确牌位建立有关联的整体观察；联系必须对问题有用 | 要求重要联系与冲突，不强迫每两张牌都发生联系，不套用其他牌组画面 |
| [Biddy Tarot：基础牌阵](https://biddytarot.com/blog/top-tarot-spreads-for-beginners/) | 包含情境、挑战、行动等结构，也允许无固定牌位共同回答问题 | 与自由摆牌相容；未填牌位就不编造过去、现在、未来。作者允许补牌，故不能把禁止补牌写成行业共识 |
| [Labyrinthos：逆位解释](https://labyrinthos.co/blogs/learn-tarot-with-labyrinthos-academy/how-to-interpret-reversed-tarot-cards) | 逆位可表现过度、减弱、阻滞或反面，须结合上下文；是否使用逆位也有个人选择 | 保留抽出的方向；避免逆位一律等于坏事或简单反义。继续标记原版资料缺少逆位条目 |
| [r/tarot：关于补牌的讨论](https://www.reddit.com/r/tarot/comments/new01p/lets_talk_about_clarifiers/) | 有人先回看已有牌和笔记，有人针对具体疑问补牌，也有人偏好自由补牌 | 只证明做法多样。产品建议不自动加牌、不为了安慰而连续重解；与既有费用保护一致 |

不把网上文章、全套牌百科、所有牌对组合或所有分析方向一起塞进请求。原版 Urban Tarot 的当前快照是事实底座；社区材料用于设计阅读方法，不替代原牌组资料。

## stage2.5.7.3 — 建议的可选项

默认：**标准、综合**。问题继续由使用者自己填写。选项改变关注角度和表达展开程度，不改变抽出的牌、位置或正逆位。

| 解读详细度 | 输出目标 |
| --- | --- |
| 简读 | 一段核心观察；每张牌一句与问题有关的贡献；一个反思问题 |
| 标准 | 简短单牌观察；最重要的联系或冲突；整体理解；1–2个反思问题 |
| 细读 | 在标准基础上，必要时增加一种替代理解，以及哪些现实信息有助区分；最多3个反思问题 |

所有档位都保留必要的来源和不确定性说明。细读不要求每次硬凑替代故事，简读也不能丢掉逆位说明。篇幅随牌数变化，先用结构目标约束，避免固定字数导致遗漏或灌水。更多文字不表示更准确。

| 分析方向 | 小段预设应强调什么 |
| --- | --- |
| 综合 | 哪些信息相互支持或冲突，整体与问题有什么关系 |
| 自我理解 | 感受、需要、假设和内在张力；不替使用者断言心理状态 |
| 行动与阻碍 | 已有资源、摩擦和本人可控的尝试；不强制清单或时间表 |
| 选择比较 | 只比较问题中实际给出的选项及其取舍；缺少选项时说明缺口，不虚构分支或保证赢家 |

先不另加爱情、事业、财运等平行模板：问题本身已携带主题。关系问题仍可使用综合或自我理解；把他人内心当成已知事实并不能增加解读质量。

界面建议：详细度、方向和模型保持可见；现有计算强度与 token 预算收在“高级”中，继续可选。这是待确认的下一步布局建议，本轮没有添加控件或隐藏现有设置。需要清楚区分：详细度控制解释展开，计算强度控制模型投入，预算是可用总输出上限而非目标篇幅。

## stage2.5.7.4 — 提示词组合与工程边界

建议每次组成：**固定事实与阅读规则 → 一个方向段落 → 一个详细度段落 → 使用者问题与当前牌阵数据**。未选择的方向不发送。既有原版含义和画面描述只发送本次牌；不自动附带共享历史或另一次占卜。使用者的问题、牌位文字作为数据处理，不能修改系统规则。

固定规则保持精简：围绕问题、遵守身份/方向/牌位、以原版文字为依据、处理真正相关的联系、保留有依据的不确定性；不要求公开逐步思维过程。OpenAI 的[推理模型提示建议](https://developers.openai.com/api/docs/guides/reasoning-best-practices)支持直接、清楚并分隔各类输入的提示方式。

OpenAI 文档区分 `reasoning.effort`（计算投入）和 `text.verbosity`（回答详细度），并建议用提示词补充具体结构要求。[官方说明](https://developers.openai.com/api/docs/guides/deployment-checklist) 未来实现前须核实两个当前模型与严格结构输出组合的实际支持情况；本轮未试调用，不能把参数兼容性或长度控制效果当作已验证。现有 `max_output_tokens` 上限、预算约束与不自动重试逻辑应独立保留。

[Prompt caching（提示缓存）](https://developers.openai.com/api/docs/guides/prompt-caching)依赖可复用前缀和模型相关设置，也可能产生写入费用。对于两人低频使用，先减少无关上下文和重复输出；是否调整缓存应测量命中、写入、费用和延迟后再决定。不要为了凑可缓存长度加入无用内容，也不承诺缓存必然省钱。

后续实现需同时覆盖：服务端白名单预设编号、版本化提示词、解读记录保存所用预设与版本、重复请求识别包含预设、待处理请求冻结不受后来选项修改影响、旧记录兼容。此处是实现时必须复核的清单，本轮未修改任何对应代码。原始模型对比证据保持冻结，不将改过的提示与旧结果混成公平模型排名。

## stage2.5.7.5 — 下一步验证建议

先做无费用的组合/结构检查，再经用户确认开展小规模配对试读：固定问题、牌和模型，只改一个选项。覆盖未命名自由摆牌、有逆位但无原书逆位说明、没有明确备选项的选择问题、询问他人想法、同一组三张牌的三种详细度。

评价问题相关性、原版忠实度、正逆位一致性、有依据的牌间联系、重复程度、详细度差异和是否凭空增加确定性；同时记录实际输入/输出用量、完整响应耗时、截断/结构失败。先确认一套提示，再比较 Terra/Sol，避免同时改变模型与框架无法归因。不自动重试失败样本，也不在此次研究中消耗余额。

最新接受记录：用户批注认可本设计，包括详细度/方向、把计算强度和预算收进高级设置，以及分段组合提示词。后续按此实施，具体实现与付费验证仍须保留各自证据；本次只记录采纳，不把研究当作已测得的质量或效率提升。
